# Session reliability fixes — 2026-09-08

แก้สามประเด็นจากรายงานศึกษาโปรเจค โดยใช้ schema เดิม ไม่ต้องเพิ่ม Supabase migration

## การซิงก์เซสชันหลังเน็ตสะดุด

- ค้นหาเซสชันเดิมด้วย gateway_session_id และ patient_id ก่อนสร้างใหม่
- ถ้ามีอีก tab สร้างเซสชันพร้อมกัน ให้กลับมาใช้ row เดิมโดยไม่แก้สถานะหรือบันทึกการตรวจของแพทย์
- ถ้าหัวเซสชันบันทึกแล้วแต่ metrics ยังไม่สำเร็จ ให้บันทึก metrics ต่อ
- ใช้ ID ของ metric ที่คำนวณซ้ำได้จาก session ID และลำดับ row พร้อม insert แบบข้าม ID ที่มีแล้ว จึงรองรับการ retry หรือการส่งซ้อน
- รองรับคิวจากโค้ดรุ่นเก่าที่บันทึก metrics ครบแล้วแต่ไม่ได้รับคำตอบ โดยตรวจจำนวน batch เดิมก่อน ไม่สร้าง metrics ซ้ำ
- ถ้าพบจำนวน metrics เดิมผิดไปจาก batch ที่อยู่ในคิว จะเก็บคิวไว้และรายงานข้อผิดพลาด ไม่ตีความว่าบันทึกครบแล้ว
- การบันทึก metrics ของแต่ละเซสชันยังเป็น bulk request เดียว ซึ่งสำเร็จหรือล้มเหลวเป็นชุด

เมื่อใช้แอปเวอร์ชันที่แก้แล้ว คิวเดิมจะใช้วิธีใหม่นี้ในการ sync ครั้งถัดไป

## Free Walk Pause/Resume

- ก่อนเริ่มและขณะ Pause ยังติดตามสถานะการเชื่อมต่อ BLE และเก็บข้อมูลสำหรับ calibration ได้ แต่ไม่ส่ง samples เข้า gait analysis
- หยุด processor ของช่วงเดินเมื่อ Pause และปฏิเสธผลจาก worker เดิมที่ส่งกลับมาช้า แม้ผู้ใช้จะ Resume แล้วก็ตาม
- Resume ใช้ buffer ใหม่พร้อม calibration เดิม เก็บ rows และจำนวนก้าวก่อนพักไว้ และนับต่อด้วย cycle key ของช่วงใหม่
- ไม่สร้าง cycle ที่เชื่อมข้อมูลก่อนพักกับหลังพัก; หลัง Resume ต้องสะสมข้อมูลใหม่อย่างน้อย 300 samples ก่อนวิเคราะห์
- ระยะเวลาที่บันทึกใช้เวลาฝึกบนหน้าจอ จึงไม่รวมช่วงพัก ส่วน start/end timestamps ยังคงเป็นเวลาจริง
- การกด End หยุดการนับด้วยกลไกเดียวกัน

## Trail Quest แยกตามบัญชี

- local save ใช้ key `derndee-save-v3:<patientId>:<Asia/Bangkok date>`
- การอ่าน การ merge และการเขียน cloud รับ patient ID ของเจ้าของข้อมูลอย่างชัดเจน
- งานค้างจากบัญชีก่อนหน้าจะไม่เลือกบัญชีปัจจุบันมาเป็นเจ้าของคะแนน และเกมถูกเริ่มใหม่เมื่อเปลี่ยนบัญชี
- คะแนนเดิมที่มีเจ้าของใน cloud ยังโหลดกลับมาได้
- key เก่า `derndee-save-v2` ไม่มีข้อมูลเจ้าของ จึงเก็บไว้ตามเดิมและไม่ย้ายเข้าใครอัตโนมัติ คะแนนที่มีเฉพาะใน key เก่าจะไม่ถูกรวมกับคะแนนใหม่

## การตรวจ

รัน `npm test`, `npm run lint` และ `npm run build` จาก DernDee_Web-app

ชุดทดสอบใช้ logic จริงกับข้อมูลสังเคราะห์และบริการจำลอง ครอบคลุม parent สำเร็จแต่ metrics ล้มเหลว, คำตอบสูญหายหลัง commit, การส่งพร้อมกัน, คิวเดิม, active duration, Pause/Resume, worker reply ที่มาช้า, การเปลี่ยนบัญชีระหว่าง hydrate และ ownerless legacy scores

การตรวจนี้ไม่แทนการทดสอบ BLE จริงหรือฐานข้อมูล production และไม่ได้ deploy การเปลี่ยนแปลงไปยังระบบออนไลน์
